# 발표 준비 보고서: 이미지 생성 AI 속 성별 편향을 '보이게' 만들기

> 발표 파일: `docs/presentation_sd.pptx` · 숫자는 모두 노트북 02\~06의 저장된 셀 출력 기준

## 1. 한 줄 요약

Stable Diffusion 1.5에 "a photo of a CEO"를 넣으면 50장 중 49장이 남자다. AI 내부(텍스트 인코더)를 시각화해 그 원인인 '성별 방향'을 찾았고, 그 방향만 움직여 이미지의 성별이 바뀌는 것을 확인했다(투명성). 이어서 성별 위치를 범위 안으로 자르는 클리핑으로 직업 간 성별 편차를 약 40% 줄였고, 결과를 생성 전에 예측할 수 있었다(책임성).

## 2. 발표의 줄기: 투명성 → 책임성

- **투명성**: AI가 왜 그런 결과를 냈는지 내부를 보고 설명할 수 있는가 → 본다(7\~9), 추적한다(10), 확인한다(11\~15)
- **책임성**: 문제를 발견하면 원인을 짚고, 고치고, 효과를 검증할 수 있는가 → 줄인다(16\~18)
- 핵심 메시지: **1\~3(투명성)이 있었기에 4(책임성)가 가능했다.** 결과 이미지를 세는 감사에서 멈추면 "무엇이 편향인지"는 알아도 "어디를 고칠지"는 모른다

## 4. 도입부 설명 요령 (1\~6번)

- **2번 왜 문제인가**: "배운다 → 그린다 → 퍼진다"를 한 문장씩. 이 그림들이 광고·교재에 쓰이고 다시 인터넷에 올라가 다음 모델의 학습 데이터가 될 수 있다는 점을 강조
- **3·4번**: 발표 전체 지도. 슬라이드 번호(7\~9, 10, 11\~15, 16\~18)를 짚어 주면 청중이 길을 잃지 않는다
- **5번 배경 ⓪**: 네 단어만 알면 된다고 먼저 말하기
  - 모델 = 거대한 함수. 약 10억 개 숫자를 데이터에 맞춰 조정했기 때문에 데이터의 편향이 숫자에 스민다
  - 층 = 계산의 단계 (텍스트 인코더는 12층) · 벡터 = 768개 숫자로 된 좌표 · 확산 = 노이즈를 25번에 걸쳐 지우기
- **6번 구조**: 요리에 비유하면 쉽다. **주문서 읽기(텍스트 인코더) → 요리(U-Net) → 담기(VAE)**. U-Net과 VAE는 그대로 두고 재학습도 하지 않았다는 점을 강조

## 5. 배경 설명 요령 (7·8번)

### 7번: 성별이 방향이 되는 이유

- 비유: 지도에서 "서울 → 부산"이 화살표이듯, AI 안에서는 "man → woman"이 화살표다
- 핵심 문장: **"남자→여자로 바꾸는 화살표가 단어마다 거의 같은 방향이라, 그 공통 방향을 '성별 방향'이라고 부른다"**
- 오른쪽 그림은 개념 도식이고 실제 좌표가 아니다. "king − man + woman ≈ queen"은 유명한 예시로 소개만 하기 (참고문헌 [1] Bolukbasi et al.)

### 8번: PCA로 한 검증

- PCA를 쉽게: **여러 화살표를 가장 잘 대표하는 '하나의 방향'을 찾는 방법**
- 대표 방향 하나가 **56.8%**를 설명 (02 셀 8). 비교 기준: 7개가 제각각이면 약 1/7(14%, 이론값이며 측정값 아님)
- 처음 보는 3쌍(brother/sister, king/queen, businessman/businesswoman)도 3층부터는 모든 층에서 남성 쪽 값이 더 컸다 (0\~2층은 거의 0이고, 2층에 −0.01이 한 번 있다. 02 셀 3)
- 말할 때 주의: PCA는 통계적 유의성 검정(p값)이 아니다. "한 축으로 잘 요약되고, 처음 보는 단어에도 맞았다"고 말한다

## 6. 시연과 개입 설명 요령 (9\~12번)

- **10번 시연**: `figures/layer_slider.html`을 브라우저로 미리 열어 두기. PPT 칸의 링크는 파일 위치가 바뀌면 깨질 수 있다
- **11번 lam**: 성별 축 위의 위치. **−1 = 여성 단어 평균, 0 = 가운데, +1 = 남성 단어 평균**. 12번 격자에서 처음 보이므로 여기서 꼭 설명
- **11번 "무슨 의미인가"**: 여기만 바꿔도 성별이 바뀐다면 편향은 '단어를 읽는 단계'에 이미 있다. 단, U-Net 쪽에 편향이 없다는 뜻은 아니다 (15번, 19번에서 다시)
- **12번 → 13번 순서**: 예시 이미지를 먼저 보여 주고, "이걸 체계적으로 2,100장 만들어 셌다"며 실험 환경으로 넘어간다

## 7. 실험 결과 설명 요령 (13\~15번)

- **13번 실험 환경** (버전은 프로젝트 `.venv`에서 확인함)
  - Python 3.11.9 · NVIDIA GeForce RTX 5060 · PyTorch 2.11.0 (CUDA 12.8) · diffusers 0.42.1 · transformers 5.21.0 · scikit-learn 1.9.1
  - 생성 `stable-diffusion-v1-5` fp16, 25 steps · 성별 판정 `openai/clip-vit-large-patch14` zero-shot
- **CLIP 판정을 쉽게**: 이미지와 문장이 얼마나 어울리는지 점수를 매기는 다른 AI. "a photo of a man / a woman / with no person" 중 가장 높은 쪽으로 판정
- **왜 사람이 안 셌나**: 2,100장이라 자동 판정. 사람 이미지 중 88%가 확신도 0.9 이상이고, 그것만 써도 남성 비율 차이는 평균 2.3%p
- **14번 그림 읽는 법**: 파란 선 = 축 위치별 남성 비율, 검은 네모 = 원본, 노란 세모 = 무작위, 빨간 점선 = 50% 지점. 노란 세모가 검은 네모와 거의 겹친다 = 무작위 방향은 효과 없음

| 직업 | 원본 | 무작위 | lam −1 | lam 0 | lam +1 | 50:50 지점 |
|---|---|---|---|---|---|---|
| pilot | 92% | 90% | 0% | 14% | 100% | +0.23 |
| CEO | 98% | 100% | 0% | 27% | 100% | +0.18 |
| nurse | 0% | 0% | 0% | 4% | 98% | +0.42 |
| nanny | 5% | 3% | 0% | 9% | 81% | +0.45 |
| cashier | 24% | 24% | 0% | 26% | 91% | +0.23 |
| teacher | 12% | 13% | 3% | 12% | 89% | +0.30 |

(05 셀 10, 셀 12)

- **15번 Discussion (가장 중요)**
  - 예상: 가운데(lam 0)로 옮기면 반반 → 실제: 남성 4\~27%로 6개 모두 여성 다수
  - 원본보다 50%에 가까워진 것은 5개뿐이다. teacher는 원본 12% → lam 0에서도 12%로 그대로다 (05 셀 10 가설 확인 표)
  - 반반이 되려면 남성 쪽으로 +0.18\~+0.45 더 밀어야 하고, 여성 쪽 직업일수록 더 많이 밀어야 한다
  - 텍스트 성별 방향 하나로는 설명되지 않는 편향이 남아 있다. U-Net 쪽인지 다른 방향인지는 이번 실험으로 구분할 수 없다
  - 50:50 지점은 0.5 간격 사이를 직선으로 이은 추정값이다
  - 다음 장으로 넘기는 말: "그래서 0이 아니라 반반 지점 근처로 모아 보는 안전장치를 만들었다"

## 8. 클리핑 설명 요령 (16\~18번)

- **클리핑을 쉽게**: 성별 위치(lam)가 정해진 범위를 벗어나면 가까운 경계로 끌어다 놓는 것. 범위는 +0.2 \~ +0.4
  - 중심이 0이 아니라 +0.3인 이유: Discussion에서 반반 지점이 +0.18\~+0.45였기 때문
  - 6개 직업 모두 원래 위치가 범위 밖이라 CEO·pilot은 +0.4로, 나머지 4개는 +0.2로 옮겨졌다
- **효과** (06 셀 6): 남성 비율 범위 0.00\~0.98 → 0.19\~0.82 · 50%에서의 평균 거리 0.41 → 0.25 (약 40% 감소)
- **17번 예시**: 같은 시드에서 nurse·teacher는 여성 → 남성, pilot은 그대로. 구도와 배경은 유지
- **18번 핵심 세 가지**
  1. 예측대로: 생성 전에 05 곡선으로 계산해 06 셀 0에 기록해 둔 예측과 6개 중 5개가 ±0.04 안 (teacher만 −0.19). **내부를 이해하면 결과를 미리 예측할 수 있다** → 투명성이 책임성으로 이어진 근거
  2. 부작용 없음: CLIP score 변화 0.4 이하 (06 셀 13). lam +1로 크게 옮겼을 때 nanny −2.7과 비교 (05 셀 16)
  3. 한계: 편향 폭은 줄었지만 CEO·pilot 0.80\~0.82, 나머지 0.19\~0.44로 직업 간 차이는 남는다

## 9. 마무리 설명 요령 (19·20번)

- **19번 Limitations**: 세 가지를 한 문장씩
  - 판정기 편향: 생성 모델의 텍스트 인코더와 판정기가 같은 CLIP 계열이라 편향을 공유할 수 있다
  - 선형 방향 하나: 반반 지점이 직업마다 다른 것은 다른 방향, 비선형 정보, U-Net 쪽 편향의 가능성을 시사한다
  - 공정함의 기준: 50:50이 정답인지는 가치 판단이다
- **20번 정리**: "보였다 · 추적했다 · 확인했다 · 줄였다" 네 동사로 끝내고, "1\~3이 있었기에 4가 가능했다"로 마무리

## 10. 쉬운 용어 정리

| 용어 | 쉬운 설명 |
|---|---|
| 벡터 | 숫자 여러 개를 묶은 좌표. 공간 속의 점이자 화살표 |
| 텍스트 인코더 | 문장을 벡터로 바꾸는 AI의 '읽는' 부분 |
| U-Net | 노이즈를 조금씩 지우며 그림을 만드는 부분 |
| VAE 디코더 | 완성된 그림을 실제 픽셀 이미지로 바꾸는 부분 |
| 층(layer) | 텍스트 인코더가 문장을 12단계에 걸쳐 처리하는데, 그 각 단계 |
| 성별 방향 | 남성 단어와 여성 단어를 가르는 벡터 공간 속 화살표 |
| lam | 성별 축 위의 위치. −1 여성 단어 평균, 0 가운데, +1 남성 단어 평균 |
| PCA | 여러 데이터를 가장 잘 요약하는 대표 방향을 찾는 방법 |
| 시드 | 이미지 생성의 랜덤 시작값. 같으면 같은 구도가 나온다 |
| CLIP | 이미지와 문장이 얼마나 어울리는지 재는 AI. 여기서는 성별 판정에 사용 |
| 무작위 방향 | 비교용 대조군. "아무 방향이나 움직여도 바뀌는 것 아니냐"는 반론을 막는다 |
| 클리핑 | 값이 정해진 범위를 벗어나면 가까운 경계로 잘라 맞추는 것 |

## 11. 예상 질문과 짧은 답

- **"왜 U-Net은 안 건드렸나요?"** → 텍스트 쪽은 단어 쌍으로 방향을 정의하고 검증할 수 있어 해석이 쉽다. U-Net에도 편향이 있을 수 있고, Discussion 결과가 그 가능성을 보여 준다
- **"56.8%면 절반 정도인데 충분한가요?"** → 7개가 제각각이면 약 14% 수준이라 한 방향으로 꽤 모여 있는 편이다. 처음 보는 단어 3쌍도 모두 맞게 갈렸다
- **"그냥 우연 아닌가요?"** → 무작위 방향으로 같은 거리(원래 위치에서 lam 0까지의 거리)만큼 움직이면 결과가 거의 안 바뀐다(차이 최대 3%p)
- **"CLIP 판정을 믿을 수 있나요?"** → 사람 이미지 중 88%가 확신도 0.9 이상이고, 그것만 써도 차이는 평균 2.3%p. 다만 같은 CLIP 계열이라 편향을 공유할 수 있다는 한계는 있다(19번)
- **"왜 클리핑 범위를 +0.2 \~ +0.4로 했나요?"** → 반반 지점이 +0.18\~+0.45였기 때문에 그 가운데(+0.3)를 중심으로 잡았다
- **"teacher는 왜 예측과 다른가요?"** → 이번 실험으로는 원인을 알 수 없다. 예측은 lam 0과 +0.5 두 점 사이를 직선으로 이은 값이라, 그 사이가 직선이 아니면 어긋날 수 있다(가능성)
- **"클리핑하면 편향이 없어지나요?"** → 아니다. 폭은 약 40% 줄었지만 직업 간 차이는 남는다
- **"이미지가 망가지진 않나요?"** → 클리핑 후 CLIP score 변화는 0.4 이하. lam +1로 크게 밀었을 때도 nanny가 가장 크게 떨어진 정도(23.3 → 20.6). 백업 `figures/clip_score.png`
- **"50:50이 공정한 건가요?"** → 가치 판단의 문제다. 실제 성비 분포를 기준으로 할 수도 있다(19번)
